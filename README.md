# autoXRAY

Личный VPN-сервер на Xray, который ставится одной командой.

Сайт на вашем домене выглядит как обычный сайт, а внутри работают VLESS, Hysteria2 и Telegram Web Proxy. Пользователей можно добавлять, ограничивать по трафику и срокам, а управляется всё одной командой `autoxray`. Без панели и без базы данных.

Проект вырос из [autoXRAY](https://github.com/xVRVx/autoXRAY) автора xVRVx и дальше живёт отдельно.

## Что понадобится

- VPS с Debian 12 или 13 (Ubuntu тоже подойдёт) и root-доступом
- домен или поддомен с одной A-записью на IP сервера
- свободные порты 80/tcp, 443/tcp и 443/udp

Некоторые хостинги заблокированы провайдерами в России. Если до сервера не доходит даже SSH без VPN, лучше взять другой.

## Установка

```bash
bash -c "$(curl -L https://github.com/cergo666/autoXRAY/releases/latest/download/install.sh)" -- вашдомен.com
```

Установщик задаст пару вопросов: нужен ли Telegram Web Proxy, какой TLS fingerprint выбрать, как назвать первого пользователя и подключать ли WARP (для него ещё спросит, насколько глубоко искать быстрый адрес и нужна ли ночная проверка). Потом выпустит сертификат, всё настроит и покажет ссылки.

Если вопросы не нужны, ответы можно передать переменными:

```bash
AX_TG=y AX_FP=2 AX_USER=anna AX_WARP=n bash install.sh вашдомен.com
```

| Переменная | Что значит |
|---|---|
| `AX_TG` | `y` или `n`, ставить ли Telegram Web Proxy |
| `AX_FP` | fingerprint: 1 chrome, 2 firefox, 3 safari, 4 ios, 5 android, 6 edge, 7 360, 8 qq |
| `AX_USER` | имя первого пользователя |
| `AX_WARP` | `n` без WARP, `y` со своим списком доменов, `ru` ещё и российские сайты через WARP |
| `AX_WARP_SCAN` | глубина поиска адреса WARP: `1` быстро, `2` подробно, `3` все адреса |
| `AX_WARP_NIGHT` | `Y` или `n`, ночная проверка адресов WARP |
| `AX_BOT_TOKEN`, `AX_BOT_ADMIN` | токен Telegram-бота и числовой ID администратора, бот настроится сам |

Если запустить установщик повторно с тем же доменом, пользователи и ключи останутся на месте.

## Куда вставлять подписку

Скопируйте ссылку подписки в приложение. Можно и проще: открыть личную страницу пользователя и нажать «Добавить в Happ».

### Одна ссылка для любого приложения

У каждого пользователя есть адрес без расширения: `https://домен/<токен>`. Его можно вставлять в любое приложение, сервер сам смотрит, кто спрашивает (заголовок User-Agent), и отдаёт подходящий формат:

| Кто спрашивает | Что получает |
|---|---|
| Happ, v2RayTun | JSON для Xray с готовой маршрутизацией (как `.json`) |
| Clash Verge, Stash, FlClash, Clash Meta и другие на Mihomo | подписку Clash (как `.yaml`) |
| sing-box (SFA, SFI), NetShift и Podkop на роутере (они представляются как `singbox/<версия>`) | подписку sing-box (как `.sing`) |
| Hiddify, v2rayNG, NekoBox, Streisand и все неизвестные | список ссылок в base64 (как `.txt`): его понимают все |
| браузер | личную страницу |

Hiddify умеет читать и Clash, и sing-box, но получает список ссылок: только в нём есть XHTTP. NetShift сначала спрашивает как sing-box и получает Vision и Hysteria2. Если в его настройках выбрать формат `xray`, он спросит как Happ и получит JSON с XHTTP (для XHTTP ему нужна сборка sing-box-extended). Если какое-то приложение получило не тот формат, дайте ему адрес с нужным расширением, он работает как раньше.

Эта ссылка теперь стоит на личной странице, в боте и в QR (`autoxray user qr anna`). QR прежнего JSON-адреса: `autoxray user qr anna json`.

| Система | Приложения |
|---|---|
| iOS, macOS | [Happ](https://www.happ.su/main/ru), [v2rayTun](https://v2raytun.com/) |
| Android | [Happ](https://www.happ.su/main/ru), [v2rayTun](https://v2raytun.com/) |
| Windows, Linux | [Happ](https://www.happ.su/main/ru), [v2rayN](https://github.com/2dust/v2rayN/releases/) |

В подписке уже есть маршрутизация: российские сайты идут напрямую, реклама блокируется. Встроенную маршрутизацию приложения лучше выключить.

Для остальных приложений (v2rayNG, NekoBox, Streisand, Hiddify и других) у каждого пользователя есть универсальная подписка: обычный список ссылок, закодированный в base64. Она лежит по адресу `https://домен/<токен>.txt`, и этот адрес показан на личной странице. Правила маршрутизации в таких приложениях придётся задать самому, готовая маршрутизация есть только в подписке для Happ и v2rayTun.

Для Clash и sing-box есть свои подписки с готовой маршрутизацией:

| Приложения | Адрес | Что внутри |
|---|---|---|
| Clash Verge, Stash, FlClash и другие на Mihomo | `https://домен/<токен>.yaml` | XHTTP, Vision, Hysteria2 |
| sing-box (SFA, SFI), версия 1.11 и новее | `https://домен/<токен>.sing` | Vision, Hysteria2 |

В sing-box нет XHTTP, поэтому там только остальные два профиля. Российские сайты идут напрямую, если у пользователя так настроено (`user set имя --ru direct|server`). Оба адреса показаны на личной странице, есть QR: `autoxray user qr имя clash` и `autoxray user qr имя sing`.

Отдельные ссылки `vless://` и `hy2://` тоже доступны: `autoxray user link имя`.

### Профиль «Авто»

Кроме трёх протоколов в подписке есть четвёртый профиль «🧭 Авто». В нём сразу все протоколы, клиент сам замеряет, какой отвечает быстрее, и ходит через него, а если один перестал работать (например, оператор режет UDP и Hysteria2 упала), переходит на другой без вашего участия. В Xray это балансировщик с замерами `leastPing`, в Clash группа `url-test`, в sing-box `urltest`. Профиль добавляется только если у пользователя осталось два протокола и больше.

Это проверено на настоящем Xray 26.3.27 из OpenWrt 25.12 (клиент) и нашем сервере: через все четыре профиля прошёл трафик. Старый клиент, то есть роутер, получает рабочий конфиг.

### Свои правила маршрутов

Правила применяются ко всем подпискам сразу (Xray, Clash, sing-box):

```bash
autoxray route add direct сайт.ру 203.0.113.0/24   # мимо сервера, напрямую с устройства
autoxray route add proxy habr.com                  # всегда через сервер
autoxray route add block ads.example.net           # блокировать на устройстве
autoxray route preset push on                      # пуш-уведомления Apple и Google напрямую
autoxray route list
autoxray route del сайт.ру
```

Принимаются домены (адреса страниц обрезаются до домена), IPv4-адреса и сети. Кириллические домены записывайте в punycode (`xn--...`). После изменения в приложении нужно обновить подписку.

### Объявления и кнопки в Happ

Happ (и частично v2RayTun) показывает над подпиской объявление и кнопки. autoXRAY отдаёт их заголовками ответа:

```bash
autoxray sub announce "Плановые работы в субботу с 2 до 3"   # объявление всем, до 200 символов
autoxray sub announce off
autoxray sub warn off                  # не показывать личные предупреждения (по умолчанию включены)
autoxray sub support @my_support       # кнопка поддержки: ссылка на Telegram или любой https://
autoxray sub support off
autoxray sub                           # что сейчас включено
```

Личные предупреждения видит только сам пользователь, они заменяют общее объявление: «⏳ Доступ до 30.11.2026» за три дня до конца срока, «⚠️ Израсходовано больше 80% трафика», «⛔ Трафик закончился» или «⛔ Срок доступа закончился». Кнопка слева в Happ ведёт на личную страницу пользователя.

Ещё один заголовок просит Happ поставить пароль на свой локальный SOCKS и HTTP прокси (`socks-auth-mode: auto`). Без пароля любое другое приложение на телефоне может отправить трафик через этот прокси мимо VPN и узнать адрес сервера. Об этой уязвимости писали весной 2026 года. В подписке sing-box у локального порта 2080 тоже есть пароль. В v2RayTun, v2rayNG и других приложениях авторизацию локального прокси проверьте в их настройках сами.

### Скрыть протокол, строка статуса, заметки

```bash
autoxray user set anna --hide hy2         # у Анны в подписках нет Hysteria2 (на сервере он остаётся)
autoxray user set anna --show all         # вернуть всё
autoxray user set anna --note "мама, оплачено до 1.12" --tags семья,vip
autoxray user find мама                   # поиск по имени, заметке и меткам
autoxray user list --tag vip
autoxray sub statusnode on                # в подписки добавится строка «Осталось 12 ГБ · до 30.11.2026»
```

Скрыть все протоколы нельзя. Строка статуса отдельным профилем без соединения и обновляется раз в пять минут. Она нужна приложениям, которые не показывают остаток трафика сами (Happ и v2rayTun показывают).

Трафик можно сбрасывать раз в неделю (по понедельникам): `--reset weekly`, или раз в месяц: `--reset monthly`.

## Управление

Просто наберите `autoxray`, откроется меню. Выбирать можно стрелками, цифрой или клавишами j и k. Выход по `q`.

Если вышла новая версия, в шапке меню появится строка с подсказкой, как обновиться.

Те же действия есть в виде команд:

```bash
autoxray user add anna --limit 50 --days 30   # 50 ГБ на 30 дней
autoxray user list                            # статусы и трафик
autoxray user link anna                       # ссылки пользователя
autoxray user qr anna                         # QR подписки в терминале
autoxray user set anna --limit 100            # новый лимит
autoxray user set anna --disable              # отключить на время
autoxray user set anna --ips 3                # не больше трёх IP-адресов одновременно
autoxray user set anna --devices 2            # не больше двух устройств (по HWID приложения)
autoxray user set anna --ru server            # российские сайты этого клиента идут через сервер
autoxray user set anna --report on            # html-отчёт о посещениях (см. ниже)
autoxray user rotate anna                     # новые ключи, старая ссылка перестанет работать
autoxray user del anna                        # удалить
autoxray stats                                # трафик по пользователям
autoxray status                               # службы, сертификат, версии
```

Лимиты трафика и сроки проверяются раз в пять минут. Тот, кто выбрал лимит или срок, отключается сам. Вернуть доступ можно командой `autoxray user set anna --reset-traffic` или продлив срок.

Чтобы трафик обнулялся раз в месяц, добавьте `--reset monthly`.

### Личная страница

У каждого пользователя свой секретный адрес вида `https://домен/<токен>.html`. На странице есть кнопки добавления в приложения, QR, все ссылки по отдельности и остаток трафика.

Саму подписку приложения берут с `https://домен/<токен>` (формат выбирается сам) или с адреса с нужным расширением. Если ссылка попала не туда, выпустите новую через `autoxray user rotate`.

### Диагностика и обслуживание

```bash
autoxray doctor        # что не так с сервером и как это исправить
autoxray firewall      # ufw: SSH, 80, 443 (спросит подтверждение)
autoxray geo-update    # обновить geoip и geosite
autoxray backup        # архив со всеми ключами и настройками
autoxray restore файл.tar.gz
```

Гео-данные обновляются сами раз в неделю. Скрипты для автоматизации могут брать вывод без оформления: `autoxray user list --plain` и `autoxray user link anna --plain`.

## Hysteria2: смена портов

Некоторые операторы замедляют долгий UDP-поток на одном порту. Hysteria2 умеет менять порт на ходу: клиент каждые 30 секунд переходит на случайный UDP-порт из диапазона, а сервер переводит весь диапазон на свой 443.

```bash
autoxray hop on                  # диапазон 20000-30000
autoxray hop on 40000-41000      # свой диапазон
autoxray hop status
autoxray hop off
```

Сервер ставит правило перенаправления в nftables (или в iptables, если nft нет), а служба `autoxray-hop` возвращает его после перезагрузки. ufw менять не нужно: пакеты перенаправляются до него и приходят уже на 443. Если у хостинга есть свой файрвол в панели, откройте там UDP-диапазон.

Подписки получают диапазон сами: Xray (маска `udphop`), Clash (`ports`), sing-box (`server_ports`), ссылка `hy2://` (`mport`). После включения обновите подписку в приложениях.

Важно: смену портов в Xray понимают только клиенты с ядром 26.9.9 и новее. Старое ядро (например, Xray 26.3.27 из OpenWrt 25.12) не запустит профили Hysteria2 и «Авто». sing-box 1.11+ и Mihomo это умеют давно. В тестах соединение пережило несколько смен порта подряд.

## WARP

WARP нужен, чтобы часть трафика уходила с сервера через Cloudflare. Профиль регистрируется сам и работает прямо внутри Xray, отдельные программы не нужны.

```bash
autoxray warp on                # зарегистрировать и включить
autoxray warp add chatgpt.com   # пускать этот домен через WARP
autoxray warp ru on             # российские сайты, дошедшие до сервера, тоже через WARP
autoxray warp ru off
autoxray warp status            # состояние и подробное объяснение, кто куда ходит
autoxray warp check             # в ответе должно быть warp=on
autoxray warp off
```

### Как это работает

Главное правило: WARP работает на сервере и касается только того трафика, который до сервера дошёл. Что клиент отправит на сервер, решает его собственная маршрутизация.

```
клиент  ->  сервер  ->  сайт              (обычный выход с сервера)
клиент  ->  сервер  ->  Cloudflare  ->  сайт   (если сайт в списке WARP)
клиент  ->  сайт                         (клиент сам пустил напрямую, сервер ничего не знает)
```

Поэтому есть два вопроса, и они независимы.

Первый: что сервер делает с тем, что получил. Это настраивается на сервере. Свои домены добавляются командой `autoxray warp add сайт.ru`. Команда `autoxray warp ru on` добавляет сюда все российские сайты.

Второй: что клиент вообще отправляет на сервер. Тут два вида клиентов.

Клиент с маршрутизацией, то есть подписка в Happ, v2rayTun и подобных. По умолчанию он открывает российские сайты напрямую с устройства, и сервер о них не знает. Чтобы такой клиент всё же отправлял российские сайты на сервер, переключите ему режим: `autoxray user set имя --ru server`. Подписку в приложении потом нужно обновить. Вернуть обратно: `--ru direct`.

Клиент без маршрутизации. Это, например, роутер или приложение, куда вы просто вставили ссылку `vless://`. Он отправляет на сервер всё, что вы ему настроили. Если на роутере выбран сайт sweb.ru, он дойдёт до сервера, и дальше всё решают правила сервера.

### Пример: роутер и один российский сайт

На роутере добавлена ссылка `vless://` и указано, что sweb.ru должен идти через неё. Нужно, чтобы сервер выпускал этот сайт через Cloudflare:

```bash
autoxray warp on
autoxray warp add sweb.ru
```

Больше ничего делать не нужно. Режим пользователя `--ru` здесь не важен, ведь это не подписка.

Если хотите, чтобы через WARP шли все российские сайты, которые приходят на сервер, включите `autoxray warp ru on`.

### Разные клиенты у разных пользователей

Режим `--ru` задаётся каждому пользователю отдельно. Одному можно оставить `direct`, и его российские сайты вообще не пойдут через сервер. Другому поставить `server`, и они пойдут через сервер и WARP. Текущий режим виден в `autoxray user list` и в `autoxray warp status`.

### Самый быстрый endpoint

У Cloudflare тысячи адресов WARP, и от выбранного зависит, на какой узел (город) попадёт ваш трафик и какая будет задержка. Чтобы не угадывать, autoxray их перебирает.

Скорость меряется через туннель на российских сайтах: yandex.ru, vk.ru и rutube.ru. Для каждого адреса поднимается тест, запрашиваются эти сайты, и берётся средняя задержка. Если ни один из сайтов через адрес не открылся, такой адрес уходит в конец списка. Сайты можно заменить: `autoxray warp hosts yandex.ru ozon.ru`.

```bash
autoxray warp scan                      # таблица: средняя задержка, узел, отклик по каждому сайту
autoxray warp scan --apply              # и сразу запомнить самый быстрый
autoxray warp scan --depth more         # глубина: quick, more или all
autoxray warp scan --exclude-colo DME   # не брать конкретный узел
autoxray warp scan --colo FRA,AMS       # только эти узлы
```

Глубина сканирования:

| Глубина | Сколько адресов | Сколько времени |
|---|---|---|
| `quick` | по одному из каждого диапазона, около 15 | несколько секунд |
| `more` | по 20 из диапазона, около 280 | 1-3 минуты |
| `all` | все адреса диапазонов, около 3500 | десятки минут |

Глубину по умолчанию вы выбираете при установке или командой `autoxray warp depth more`. `autoxray warp on` ищет адрес с этой глубиной и выбирает лучший.

Выбор идёт в два этапа. Сначала замер скорости по всем адресам. Затем самые быстрые (по умолчанию три, плюс текущий) проверяются на стабильность: серия запросов с паузой простоя посередине. Побеждает тот, у кого нет провалов, а среди равных самый быстрый. Это важно: самый быстрый адрес иногда зависает на 10-25 секунд, и лучше чуть более медленный, но надёжный. Второй этап настраивается: `autoxray warp stable off` или `autoxray warp stable top 5`.

### Ночная проверка

Адрес со временем может стать хуже, поэтому его можно перепроверять по ночам (при установке спросит, по умолчанию включено):

```bash
autoxray warp nightly on         # включить
autoxray warp threshold 300      # порог задержки в миллисекундах
autoxray warp rescan now         # запустить проверку прямо сейчас
```

Как это работает. Каждую ночь проверяются 15 лучших адресов, найденных в прошлый раз. Если лучший из них быстрее порога (по умолчанию 300 мс), он и становится рабочим. Если все медленнее порога или недоступны, пересканируется весь набор выбранной глубины, и запоминается новый топ.

Адрес заменяется, только если новый заметно лучше текущего (минимум на 10%). Так Xray не перезапускается ради пары миллисекунд. Результат последней проверки виден в `autoxray warp status`, история лежит в `/etc/autoxray/warp-rescan.log`.

Диапазоны адресов и сам подход взяты из [warpscout](https://github.com/vernette/warpscout).

### Первый запрос после простоя медленный

Знакомая картина: сайт через WARP не открывался несколько минут, первый заход ушёл в таймаут, со второго раза всё летает. Это холодный туннель.

Почему так. Xray создаёт WireGuard-устройство лениво, только на первом запросе. А сессия WireGuard без трафика устаревает за пару минут, и следующему запросу приходится заново делать рукопожатие с Cloudflare. Если первый пакет рукопожатия потерялся (UDP это бывает), WireGuard повторяет его только через 5 секунд, и клиент с коротким таймаутом, например роутер, успевает сдаться.

Что сделано. У WARP включён keepalive (каждые 25 секунд), а раз в минуту cron отправляет через туннель крошечный запрос, и после каждого перезапуска Xray туннель прогревается сразу. Настройки:

```bash
autoxray warp keepalive 25      # keepalive WireGuard в секундах, 0 выключает
autoxray warp keepwarm on       # прогрев раз в минуту (по умолчанию включён)
autoxray warp status            # в строке «Прогрев» видно, отвечает ли туннель
```

Если проблема осталась, её можно разобрать по слоям:

```bash
autoxray warp coldtest --idle 200 --site sweb.ru
```

Команда поднимает отдельный Xray с вашим WARP и сравнивает холодный запрос, сразу второй и запрос после простоя. Заодно показывает, сколько раз повторялось рукопожатие и как быстро отвечают DNS-серверы. В конце она объясняет, что не так: потери UDP до адреса, медленный DNS или остывающий туннель.

Команда отдельно проверяет сам туннель (запрос к Cloudflare, видно IP выхода) и сайт. Если туннель исправен, а первое соединение к сайту не доходит, и только следующие открываются, дело в стороне сайта. Защита от DDoS у хостингов часто не пускает первые соединения с незнакомого IP, а у WARP выходной IP может меняться. Здесь помогает прогрев нужного сайта, он раз в минуту запрашивается через WARP:

```bash
autoxray warp warmhosts sweb.ru     # сайт должен идти через WARP (warp add или режим для российских сайтов)
autoxray warp warmhosts off
```

Если запросы через туннель то проходят, то зависают на 10-25 секунд, проверьте стабильность. Самый быстрый по замеру endpoint может иногда «молчать», пока WireGuard через 15 секунд не заметит это и не сделает рукопожатие заново:

```bash
autoxray warp soak                # серия запросов по лучшим endpoint'ам, таблица провалов
autoxray warp soak --apply        # и запомнить самый стабильный
autoxray warp renew               # если проваливаются все: новое устройство Cloudflare (новый ключ)
```

Для разбора того, что происходит на самом сервере, есть временный подробный лог:

```bash
autoxray debug on 30            # на 30 минут (потом выключится сам)
# воспроизведите проблему: зайдите на сайт после простоя
autoxray debug show sweb.ru     # рукопожатия, DNS и обращения к этому сайту с метками времени
autoxray debug off
```

В подробном логе видны адреса, на которые ходят пользователи, поэтому он выключается сам и очищается.

### WARP через MASQUE (экспериментально)

Если провайдер режет WireGuard (UDP 2408), можно подключить WARP через MASQUE: это IP-туннель поверх HTTP/3 на порту 443, он выглядит как обычный HTTPS и не требует подбора адреса.

```bash
autoxray warp transport masque      # зарегистрирует отдельное устройство и переключит
autoxray warp transport wireguard   # вернуться
```

Команда сама проверяет, что туннель заработал (`warp=on`). Если нет, она возвращает WireGuard и пишет об этом. `--force` оставляет MASQUE без проверки. Профиль WireGuard и MASQUE хранятся отдельно, переключение ничего не стирает. В режиме MASQUE сканирование и выбор endpoint отключены: адрес выдаёт Cloudflare.

Регистрация идёт так же, как у приложения WARP для Android (с его заголовками), поэтому Cloudflare может изменить API. Тесты проверяют формирование конфига, принятие его ядром Xray 26.10 и откат на подменённом API. Настоящая регистрация и работа туннеля у Cloudflare в тестах не участвуют, их можно проверить только на своём сервере командой выше.

### Проверка и отладка

Перед включением autoxray проверяет, что WARP вообще отвечает с вашего сервера, и перебирает несколько адресов и портов Cloudflare. Если не отвечает ни один, WARP не включится. Это сделано специально: иначе российские сайты перестали бы открываться.

Если WARP не заводится, запустите `autoxray warp debug`. Команда соберёт отчёт, в котором секретные ключи скрыты, и его можно спокойно показывать.

Примут ли конкретные сайты адреса Cloudflare, зависит от самих сайтов. Проверьте на тех, что вам нужны.

## Устройства и их лимит

Happ, v2RayTun, NetShift и некоторые другие приложения присылают с запросом подписки свой идентификатор устройства (HWID), а также ОС и модель. По ним autoXRAY ведёт список устройств каждого пользователя:

```bash
autoxray user devices anna           # модель, ОС, приложение, когда обновляло подписку
autoxray user set anna --devices 2   # не больше двух устройств, 0 убирает лимит
autoxray user devices anna del 1     # удалить устройство и освободить место
```

Когда лимит исчерпан, новое устройство получает вместо подписки ошибку 403. Администратор и сам пользователь (если он привязал Telegram) получают уведомление, а в боте есть кнопки «📱 Устройства» и команда `/devices`: там видно список и можно удалить старое устройство.

Ограничения:

- Лимит действует только на получение подписки. Устройство, которое уже получило конфиг, продолжает работать, пока вы не выпустите новые ключи (`autoxray user rotate`).
- Приложения, которые не присылают HWID (Clash, v2rayNG, sing-box и другие), не считаются и не ограничиваются. Строгий лимит по подключениям даёт лимит IP-адресов (ниже).
- Новое устройство попадает в список при ближайшем разборе, раз в пять минут. Если за это время подписку получат несколько новых устройств сразу, лишние попадут в список как «не допущено», и при следующем обновлении подписки получат 403.
- Устройство, которое 60 дней не обновляло подписку, забывается и освобождает место.

## Лимит IP-адресов

Можно ограничить число разных IP-адресов, с которых одновременно пользуются одним доступом:

```bash
autoxray user set anna --ips 3
autoxray ips                 # кто и с каких адресов сейчас подключён
autoxray unban anna          # снять блокировки
```

Свои адреса можно объявить доверенными: они не занимают место и не блокируются. Это удобно для домашнего IP или сети мобильного оператора, у которого адрес постоянно меняется:

```bash
autoxray user set anna --trust 203.0.113.5          # один адрес
autoxray user set anna --trust 203.0.113.0/24       # сеть IPv4 (от /8 до /32)
autoxray user set anna --untrust 203.0.113.5        # убрать, all убирает все
```

Первые три адреса считаются своими. Четвёртый и следующие блокируются на 30 минут, остальные продолжают работать. Адрес освобождает место, если от него десять минут нет активности. Устройства из одной домашней сети делят один IP, поэтому считаются за одно.

Блокировка действует на новые подключения. Уже установленное соединение с лишнего адреса может дожить до своего конца.

Для работы лимита Xray включает журнал доступа. В нём видны адреса и сайты, к которым обращались. Журнал разбирается и очищается раз в минуту, а если лимитов ни у кого нет, он вообще выключен.

## Telegram-бот для управления

Сервером можно управлять из Telegram. Бот отвечает только администраторам из вашего списка, остальных он просто не замечает.

```bash
autoxray bot setup        # токен от @BotFather и первый администратор
autoxray bot status
autoxray bot add-admin 123456789
autoxray bot off          # выключить
```

Как настроить. Создайте бота у @BotFather командой `/newbot` и скопируйте токен. Запустите `autoxray bot setup`, вставьте токен, потом откройте своего бота и отправьте ему любое сообщение. autoxray покажет имя и ID того, кто написал, и спросит, сделать ли его администратором. Узнать свой числовой ID можно и командой `/id` в боте, она работает у всех.

Что умеет бот. Команда `/users` показывает пользователей кнопками, нажатие открывает карточку: ссылки, QR, лимиты (одной кнопкой), отключение, новые ключи, отчёт, удаление. Всё опасное (удаление, новые ключи, включение отчёта) просит подтверждение. Есть и обычные команды: `/add имя 50 30`, `/limit`, `/days`, `/ips`, `/ru`, `/report`, `/link`, `/stats`, `/status`, `/doctor`, `/warp`, список в `/help`.

Отчёт о посещениях бот присылает прямо в чат: команда `/report имя` отправляет сводку текстом (топ адресов с описанием и IP клиента), затем html-файл и ссылку на ту же страницу. Кнопка «Отчёт» в карточке пользователя делает то же самое, выключить отчёт там же. Включить и выключить по-прежнему можно командой `/report имя on|off`. Доверенные адреса задаются командами `/trust имя адрес` и `/untrust имя адрес`.

Копию настроек бот тоже может прислать. Это архив с ключами и паролями, а Telegram хранит файлы на своих серверах, поэтому архив всегда шифруется паролем, который задаёте вы. Без пароля бот копию не отправляет.

```bash
autoxray bot backup pass     # задать пароль (запомните его: без него копию не открыть)
autoxray bot backup on       # раз в неделю присылать копию сам
autoxray bot backup now      # прислать сейчас (в боте то же делает /backup)
autoxray restore файл.tar.gz.enc   # восстановление спросит пароль
```

Бот сам пишет вам, когда пользователь впервые подключился, когда израсходовано 80% лимита или до конца срока осталось три дня (каждое предупреждение приходит один раз), когда кончился лимит или срок, когда заблокирован лишний IP, когда WARP сменил endpoint, вышла новая версия, сертификат скоро истечёт или упала служба.

Бот сам следит за версией: если файл `autoxray` заменили (обновление, ручная установка), служба выходит и systemd запускает её заново, так что она не остаётся на старом коде. Версия бота видна в `/help`.

Безопасность. Токен лежит в `/etc/autoxray/bot.token` с правами 600 и не попадает ни в аргументы процессов, ни в журналы. Бот отвечает только в личных чатах и только админам, аргументы команд проверяются, к оболочке они не доходят. Если токен утёк, отзовите его у @BotFather и выполните `autoxray bot setup` заново.

Если сервер в России и api.telegram.org недоступен, укажите прокси: `autoxray bot setup --proxy socks5h://адрес:порт` или `autoxray bot proxy ...`.

### Бот для клиентов

Клиент может сам смотреть свой трафик и срок. Администратор выдаёт приглашение:

```bash
autoxray user invite anna    # ссылка https://t.me/<бот>?start=<код>, одноразовая, 7 дней
autoxray user unlink anna    # отвязать Telegram
```

То же в боте: кнопка «✉️ Пригласить» в карточке или `/invite имя`. Клиент открывает ссылку, нажимает «Запустить», и бот привязывает его Telegram к пользователю. После этого клиенту доступно только своё: `/me` (трафик, срок, статус), `/link` (ссылки подписки), `/qr`, `/devices` (свои устройства, можно удалить старое). Управлять сервером он не может. Ему же приходят предупреждения: израсходовано 80% трафика, до конца срока три дня, лимит исчерпан, доступ закрыт или снова открыт. Приглашение предъявить может любой, у кого есть ссылка, но подобрать код нельзя: после пяти неверных попыток за час бот молчит.

Администратор может написать всем привязанным клиентам: `/broadcast текст`. Бот сначала покажет текст и число получателей и отправит только после подтверждения.

Для администратора в боте добавились `/note`, `/tags`, `/find`, `/hide`, `/show` (то же, что в консоли), `/unlink` и `/devices имя [лимит]` с кнопками удаления устройств.

## Сайт-маскировка

Сайт на домене генерируется случайно при установке: дизайн, тексты, путь формы входа. Его можно сменить без переустановки.

```bash
autoxray site regenerate        # новый случайный дизайн
autoxray site set ~/mysite      # свой статический сайт (в папке должен быть index.html)
autoxray site status
```

Файлы подписок при этом не затрагиваются. Имена из 20-32 латинских букв и цифр с расширением `.json`, `.html`, `.txt`, `.yaml` или `.sing` зарезервированы под подписки, в своём сайте их лучше не использовать.

```bash
autoxray telegram update    # обновить
autoxray telegram remove    # убрать
```

## Мост RU → EU

Бывает, что подсеть зарубежного хостинга режут, особенно в мобильных сетях. Тогда ставят сервер в России, а он уже пересылает трафик за границу.

Сначала поставьте обычный сервер на зарубежный VPS. Из его `autoxray user link <имя> --plain` возьмите первую ссылку (XHTTP). Для нескольких зарубежных серверов создайте по пользователю на каждом.

Потом на российском VPS:

```bash
bash -c "$(curl -L https://github.com/cergo666/autoXRAY/releases/latest/download/install.sh)" -- мост.вашдомен.com "vless://узел1" "vless://узел2"
```

Дальше цепочка такая: клиент, российский сервер, зарубежный сервер, сайт. Если узлов несколько, в подписке появится профиль «Автобалансир» и отдельные профили на каждый узел.

Узлы меняются так:

```bash
autoxray node list
autoxray node add "vless://..."
autoxray node del <имя или номер>
```

Узлы принимаются с `security=tls` или `none`. REALITY не поддерживается. WARP в режиме моста не нужен, российский трафик там и так идёт напрямую.

## Обновление

```bash
autoxray self-update     # сам autoxray, до последнего релиза
autoxray rollback        # вернуться к состоянию до обновления
autoxray core list       # какая версия Xray стоит и какие новее (пререлизы помечены)
autoxray core update     # обновить ядро
```

`self-update` безопасное. Перед заменой он делает снимок: скрипт, шаблоны, настройки, конфиги Xray и nginx, расписание. После обновления проверяются конфиги, работа служб и то, что подписка открывается по HTTPS. Если что-то не так, всё возвращается назад само, и вы увидите, что именно не прошло проверку. Три последних снимка хранятся в `/var/lib/autoxray/snapshots/`, ими можно воспользоваться и позже через `autoxray rollback`.

Перед обновлением загляните в [заметки к релизу](https://github.com/cergo666/autoXRAY/releases). Там написано, нужно ли после него обновлять подписки в клиентах.

Файлы релиза сверяются с контрольными суммами. Вместе с релизом публикуется `FILES.sha256`, и `install.sh` (когда он закреплён на тег) и `self-update` проверяют каждый скачанный файл до установки. Если суммы не совпали или их не получилось скачать, ничего не ставится. Это защищает от порчи или подмены файлов при скачивании. От подмены в самом репозитории это не защищает: суммы лежат в том же релизе.

Ядро Xray без нужды лучше не трогать. В новых версиях иногда меняется формат конфигов, и то, что работало, может сломаться. Каждый релиз autoXRAY проверен с одной конкретной версией ядра (сейчас v26.10.21), она показывается в `autoxray core list`. Версии 26.10.10 и 26.10.17 разработчики Xray отозвали из-за утечки приватных ключей промежуточных сертификатов, в v26.10.21 они исправлены. Пререлизы в списке есть, но помечены отдельно и для постоянной работы не подходят. Если после обновления конфиг перестанет проходить проверку, прежняя версия вернётся сама.

### Переход с autoXRAY 2

Запустите установщик с тем же доменом на том же сервере. Он найдёт старую установку и предложит перенести её. UUID, пароль Hysteria2 и адрес подписки сохранятся, клиентам ничего менять не придётся. Старый конфиг останется в `/etc/autoxray/config.v2.json.bak`.

## Удаление

```bash
autoxray uninstall
```

Команда спросит подтверждение и удалит Xray, nginx, сайт, Web Proxy и все данные. Если ключи ещё нужны, сначала сделайте `autoxray backup`.

## Где что лежит

| Путь | Что там |
|---|---|
| `/etc/autoxray/state.json` | всё, что вы настроили: пользователи, пути, WARP, узлы |
| `/etc/autoxray/traffic.json` | счётчики трафика |
| `/etc/autoxray/devices.json` | устройства пользователей (HWID, модель, ОС, приложение) |
| `/etc/nginx/autoxray-*.map` | заголовки подписки, объявления и разрешённые устройства для nginx |
| `/usr/local/etc/xray/config.json` | конфиг Xray, создаётся автоматически |
| `/etc/nginx/conf.d/default.conf` | конфиг nginx, тоже автоматический |
| `/var/www/<домен>/` | сайт и файлы подписок |
| `/var/lib/xray/cert/` | сертификат |

Править `config.json` вручную бесполезно, при следующем изменении он пересоберётся из `state.json`. Если всё же правите `state.json`, потом выполните `autoxray render`.

Перед применением каждый конфиг проверяется. Если проверка не пройдена, остаётся прежний.

## Отчёты о посещениях

По желанию для каждого пользователя можно включить html-отчёт: на какие сайты и адреса он ходил, с каких IP, в какое время. Отчёт выключен, пока вы его явно не включите.

```bash
autoxray user set anna --report on     # включить
autoxray user set anna --report off    # выключить, страница удалится
autoxray report list                   # у кого включён и адреса отчётов
autoxray report url anna               # адрес отчёта anna (без имени: список для администратора)
autoxray report keep 30                # сколько дней хранить (по умолчанию 30)
autoxray report purge anna             # удалить накопленные данные сразу
```

У каждого пользователя своя страница со своим секретным адресом вида `https://домен/r/<токен пользователя>/`. Её можно отдать самому пользователю: по ней не видно ни чужих отчётов, ни их списка.

Список всех отчётов открывается по отдельному адресу администратора, его покажет `autoxray report list` (или `autoxray report url` без имени). Страница пользователя показывает:

- число подключений, уникальные адреса, IP клиента и сколько заблокировано (реклама, трекеры)
- график по часам
- топ адресов с долями, можно сгруппировать по доменам
- с каких IP заходил, и что делал с каждого
- порты и куда ушёл трафик: напрямую, через WARP или в блок
- ранжирование по дням, любой день открывается кликом, есть сводка за 7 и 30 дней

К адресам в отчёте дописывается, что это такое: флаг и код страны, номер и название сети (AS), для многих ещё обратная DNS-запись. Так `149.154.167.222` превращается в «AS62041 Telegram». Данные берутся DNS-запросами с сервера (сервис Team Cymru и обычные PTR-записи), хранятся в `/etc/autoxray/ipinfo.json` 30 дней и дополняются постепенно, не больше сорока новых адресов за сборку. Страна здесь страна регистрации сети, а не расположение сервера: у Telegram это Антигуа, у многих CDN США. Частные адреса не опрашиваются.

Перед названиями сайтов показываются их иконки. Их загружает браузер при открытии отчёта с `icons.duckduckgo.com`, поэтому DuckDuckGo видит список сайтов из отчёта. Если это не подходит, `autoxray report icons off`, и страница не обращается к сторонним сайтам.

Отчёт самодостаточный: графики и списки за последние 7 дней собраны на сервере и лежат в самом файле, поэтому html открывается правильно и там, где скрипты не работают (встроенный просмотр файлов в Telegram). В браузере к ним добавляются выбор дня, 30 дней и переключатель «по доменам». Сводку можно прочитать и в консоли: `autoxray report summary имя`.

Подключение здесь это одно TCP-соединение или UDP-поток. Адреса показаны так, как их запросил клиент: если приложение просит домен, виден домен, если сразу IP, виден IP. Время в отчёте серверное.

Как это устроено. Для отчётов Xray ведёт журнал доступа. Раз в минуту журнал разбирается в суточные счётчики и тут же очищается. Хранятся только счётчики по дням (какой адрес сколько раз, с какого IP, в какой час), а не последовательность посещений. Данные лежат в `/etc/autoxray/reports/` с правами 700, а страницы для просмотра в `/var/lib/autoxray/reports/`.

Это слежка за пользователем, поэтому включайте отчёт только с его ведома. Страницу видит любой, у кого есть адрес с токеном, не показывайте его посторонним.

### Попытки торрента

Сервер блокирует BitTorrent всегда. Если нужно узнавать, кто пытается: `autoxray torrent alert on` (бот напишет не чаще раза в час на пользователя). Для этого Xray ведёт журнал доступа, который очищается раз в минуту, как при лимите IP. Важное ограничение: подписки autoxray отправляют торрент напрямую с устройства, мимо сервера, поэтому сервер видит только клиентов без такой маршрутизации, например ссылку `vless://` в роутере.

## Какие данные хранятся на сервере

Адреса сайтов, которые открывают пользователи, не хранятся. Исключения: лимит IP-адресов и отчёты о посещениях, если вы их включили.

| Что | Где | Сколько живёт |
|---|---|---|
| Журнал доступа Xray: IP клиента, сайт, пользователь | `/var/log/xray/access.log` | Пишется только если у кого-то задан лимит IP или включён отчёт. Очищается каждую минуту |
| Журнал ошибок Xray | `/var/log/xray/error.log` | Только при лимите IP или отчёте. Обнуляется при превышении 20 МБ |
| IP клиентов с лимитом | `/etc/autoxray/ips.json` | Пока от адреса есть активность и ещё 10 минут после |
| Заблокированные IP | `/etc/autoxray/bans.json` | 30 минут |
| Суточные счётчики для отчёта: адрес, IP клиента, час, число | `/etc/autoxray/reports/<имя>/` | Только у тех, кому включён отчёт. 30 дней, срок настраивается |
| Страница отчёта | `/var/lib/autoxray/reports/<токен>/` | Пока отчёт включён |
| Счётчики трафика | `/etc/autoxray/traffic.json` | Только число байт на пользователя, без адресов |
| Запросы подписок: время, адрес подписки, HWID, ОС, модель, приложение (без IP) | `/var/log/nginx/autoxray-sub.log` | Очищается раз в пять минут после разбора |
| Устройства: HWID, модель, ОС, приложение, первый и последний запрос подписки | `/etc/autoxray/devices.json` | 60 дней после последнего запроса подписки |
| nginx, остальное | журнал доступа выключен | Ничего не пишется |

Если лимитов и отчётов нет, Xray не пишет журналы вообще, а остатки очищаются при ближайшем запуске `autoxray ipwatch` (раз в минуту из cron). Если журнал всё же вырастет больше 20 МБ, он обнуляется. `autoxray doctor` предупредит, если с журналом что-то не так.

## Несколько советов по безопасности

Смените порт SSH или оставьте вход только по ключу. Закройте всё лишнее файрволом, в этом поможет `autoxray firewall`.

Личные страницы пользователей не стоит никому показывать: адрес страницы и есть пароль. Бэкапы храните отдельно, в них лежат приватные ключи.

## Для разработчиков

Тесты запускаются в Docker с настоящими Xray и nginx:

```bash
tests/run.sh all        # всё сразу, наборы идут параллельно (AX_SERIAL=1: по очереди)
tests/run.sh direct     # один сценарий: direct, bridge или install
tests/check-version.sh  # версии в файлах совпадают
```

Они гоняют через сервер трафик по каждому протоколу, проверяют лимиты, WARP, мост из двух серверов, установщик и переход с версии 2. Внешние сервисы вроде apt, ACME и Cloudflare заменены заглушками.

### Релизы

Версии идут по [SemVer](https://semver.org/lang/ru/), изменения описаны в [CHANGELOG.md](CHANGELOG.md). Ставить лучше релиз, ветка `main` это работа в процессе. Состояние до версии 3 сохранено тегом `v2-legacy`.

Чтобы выпустить релиз:

```bash
tools/bump-version.sh 3.3.0
# допишите CHANGELOG, потом
git commit -am "Release v3.3.0" && git tag -a v3.3.0 -m "v3.3.0" && git push origin main v3.3.0
```

Тег запускает [workflow](.github/workflows/release.yml). Он проверит версии, прогонит тесты, соберёт `install.sh` под этот тег и опубликует релиз с заметками из CHANGELOG.
