## [3.11.0] — 2026-10-21

### Added
- Подписки для Clash/Mihomo (`<токен>.yaml`: XHTTP, Vision, Hysteria2) и sing-box (`<токен>.sing`: Vision, Hysteria2, версия 1.11 и новее). Маршрутизация RU по режиму пользователя, заголовок `subscription-userinfo`, ссылки и QR на личной странице, `user qr имя clash|sing`. Оба формата проверены настоящими sing-box 1.14 и Mihomo 1.19 (`check` и `-t`).
- Доверенные адреса для лимита IP: `user set имя --trust IP|сеть` и `--untrust IP|all`. Доверенный адрес не занимает место и не блокируется. Команды `/trust` и `/untrust` в боте.
- Бот присылает отчёт о посещениях html-файлом и ссылкой: `/report имя` и кнопка «Отчёт» (файл, ссылка, выключить).
- Зашифрованная копия настроек в Telegram: `autoxray bot backup pass|now|on|off`, команда `/backup`, раз в неделю автоматически. Без пароля не отправляется, пароль в архив не попадает. `autoxray restore` понимает файлы `.enc`.
- Уведомления бота: первое подключение пользователя, 80% лимита, три дня до конца срока (каждое один раз).


## [3.10.0] — 2026-10-19

### Fixed
- Пользователь с истёкшим сроком продолжал работать: `collect` пересобирал конфиг Xray только при изменении лимитов. Теперь конфиг пересобирается каждый раз, а Xray перезапускается, только если конфиг действительно изменился.
- `user add --days 0` создавал сразу истёкшего пользователя, теперь это «бессрочно», как и в `user set`.
- Без активных пользователей каждый `render` менял конфиг (случайные ключи-заглушки) и перезапускал Xray. Заглушки теперь постоянные.
- Режим моста: пока у балансировщика нет замеров (первые секунды после перезапуска) или все узлы не ответили, трафик уходил напрямую с российского сервера. Теперь он идёт на первый EU-узел.
- Кнопка QR в Telegram-боте отправляла картинку не в тот чат и с пустой ссылкой (перепутаны аргументы).
- `user qr <имя> xhttp|vision|hy2` в режиме моста показывал не те ссылки: теперь ссылка ищется по названию.
- Обновление гео-данных из cron всегда завершалось ошибкой: новый официальный установщик Xray падает без переменной TERM. Если установщик не скачался, `core update`, `geo-update` и `uninstall` больше не считают это успехом, а `core update` проверяет, что установилась нужная версия. О неудачном обновлении гео-данных приходит уведомление в бот.
- `self-update` берёт список файлов из новой версии, а не из текущей: новые шаблоны будущих релизов скачаются.
- Неудачный `bot setup` с неверным токеном удалял прежний рабочий токен. Теперь новый токен проверяется отдельно, а на время ожидания сообщения служба бота останавливается, чтобы не забирать его себе.
- `warp soak --apply` больше не применяет endpoint, который не ответил ни разу. Две проверки стабильности одновременно (ручная и ночная) больше не мешают друг другу.
- `user del` удаляет известные IP и блокировки пользователя: новый пользователь с тем же именем их не наследует.
- `uninstall` удаляет и `/var/lib/autoxray` (снимки обновлений с ключами, страницы отчётов).
- `install.sh` при повторной установке в режиме моста больше не спрашивает про WARP; установщик Xray не падает без TERM.
- `init` с параметром без значения даёт понятную ошибку.

### Changed
- Отчёты о посещениях: у каждого пользователя своя секретная ссылка `/r/<токен пользователя>/`, её можно отдать самому пользователю, чужие отчёты и список по ней не видны. Список отчётов для администратора открывается по отдельной ссылке (`autoxray report url`). Старые адреса `/r/<токен>/<имя>/` больше не работают, новые покажет `autoxray report list`.
- Если изменились только счётчики трафика в заголовке подписки, nginx перечитывает конфиг не чаще раза в час: каждый reload оставляет старые процессы nginx, пока живы длинные соединения XHTTP.
- Библиотека QR на личной странице подключается с проверкой целостности (SRI).
- Тесты: наборы `tests/run.sh all` идут параллельно, проверка гео-данных не ходит в сеть, фиксированные паузы заменены ожиданием по факту, добавлены проверки на все исправления выше.


## [3.9.0] — 2026-10-18

### Changed
- Выбор endpoint'а WARP теперь двухэтапный: сначала замер скорости, затем среди самых быстрых (по умолчанию трёх, плюс текущий) проверка стабильности (серия запросов с паузой простоя), и выбирается самый стабильный, а при равенстве самый быстрый. Так работают `warp on`, `warp scan --apply` и ночная проверка. Текущий endpoint сохраняется, если он не хуже по провалам и повторам рукопожатия и не медленнее лучшего более чем на 10%.
- Если проверка стабильности не дала ни одного ответа, остаётся выбор по скорости.

### Added
- `autoxray warp stable on|off|top N`: включить или выключить второй этап и задать, сколько лучших проверять. `warp scan --no-soak` пропускает второй этап.


## [3.8.0] — 2026-10-18

### Added
- `autoxray warp soak [--apply] [--rounds N] [--idle СЕК] [endpoint...]`: проверка стабильности endpoint'ов. Для каждого отдельный тестовый Xray, серия запросов к российским сайтам с паузой простоя посередине, таблица «успешно, провалов, средняя задержка, повторов рукопожатия». Самый быстрый по замеру endpoint может «зависать», поэтому выбирать по стабильности надёжнее. `--apply` запоминает самый стабильный.
- `autoxray warp renew`: новое устройство Cloudflare (новый ключ) с сохранением endpoint, доменов и режимов, старое устройство удаляется. Нужно, если проваливаются все endpoint'ы.


## [3.7.2] — 2026-10-18

### Changed
- `autoxray warp coldtest` разделяет вину туннеля и сайта: сначала запрос к самому Cloudflare (trace: исправность туннеля, IP выхода и узел), затем три запроса к сайту подряд и запрос после простоя с проверкой, не сменился ли IP выхода. По итогам даёт вывод, на чьей стороне задержка первого соединения.
- Режим «российские сайты через WARP» теперь учитывается при определении маршрута сайта (раньше показывалось «в списке WARP: нет»).

### Added
- `autoxray warp warmhosts <сайты>|off|list`: сайты, которые раз в минуту запрашиваются через WARP вместе с прогревом, чтобы защита от DDoS у сайта считала IP выхода знакомым.


## [3.7.1] — 2026-10-18

### Fixed
- `autoxray warp coldtest` при ошибке подставлял «нет ответа за 25 с» вместо настоящего времени и причины. Теперь показываются реальные время и ошибка curl.

## [3.7.0] — 2026-10-18

### Fixed
- Первый запрос после простоя через WARP мог уходить в таймаут: Xray создаёт WireGuard-устройство только на первом запросе, а сессия без трафика устаревает, и потерянный первый пакет рукопожатия давал задержку в 5 секунд. Теперь у WARP включён keepalive 25 с, раз в минуту идёт прогревающий запрос (`autoxray warp warm` из cron), а после каждого перезапуска Xray туннель прогревается сразу.

### Added
- `autoxray warp coldtest [--idle СЕК] [--site домен]`: сравнение холодного, тёплого запроса и запроса после простоя, счётчик рукопожатий WireGuard, скорость DNS-серверов и вывод о причине.
- `autoxray warp keepalive N`, `autoxray warp keepwarm on|off`, строка «Прогрев» в `warp status`. Если WARP не отвечает три проверки подряд, бот присылает уведомление.
- `autoxray debug on [минут] | show [сайт] | off`: временный подробный лог Xray с журналом DNS, выключается сам.


## [3.6.0] — 2026-10-17

### Added
- Telegram-бот администратора (`autoxray bot setup`): управление пользователями кнопками и командами, подтверждение опасных действий, QR, ссылки, статус и диагностика. Отвечает только администраторам в личных чатах. Токен хранится с правами 600 и не попадает в аргументы процессов и журналы. Работает как служба `autoxray-bot`.
- Уведомления бота: исчерпан лимит или срок пользователя, заблокированный IP, смена endpoint WARP, новая версия, срок сертификата, упавшие xray и nginx.
- Универсальная подписка `https://домен/<токен>.txt` (base64 со ссылками) для v2rayNG, NekoBox, Streisand, Hiddify и других; карточка на личной странице, `autoxray user qr имя links`.
- Безопасное обновление: `self-update` делает снимок, проверяет конфиги, службы и подписку и сам откатывается при сбое. Команда `autoxray rollback`, три последних снимка.
- `autoxray site regenerate|set|status`: новый случайный сайт-маскировка или свой статический сайт без переустановки.
- Меню: разделы «Telegram-бот» и «Обслуживание».


## [3.5.0] — 2026-10-16

### Added
- Отчёты о посещениях для каждого пользователя (`autoxray user set имя --report on`): html с топом адресов, IP клиента, графиком по часам, портами, долей прямого, WARP и заблокированного трафика, ранжированием по дням и сводками за 7 и 30 дней. Данные копятся суточными счётчиками (без последовательности посещений), хранятся 30 дней, страница отдаётся по секретному адресу `/r/<токен>/<имя>/`. Команды `autoxray report list|build|url|purge|keep`.
- Ночная проверка endpoint'ов WARP: перепроверка 15 лучших адресов, при задержке выше порога (300 мс) полный пересмотр набора выбранной глубины, новый топ сохраняется. Команды `warp nightly|threshold|depth|rescan|hosts`, запись в cron. Endpoint заменяется, только если новый лучше текущего минимум на 10%.
- Глубина сканирования WARP: `quick` (около 15 адресов), `more` (около 280), `all` (около 3500). Вопросы об этом в установщике.

### Changed
- Скорость endpoint'а меряется через туннель на российских сайтах (yandex.ru, vk.ru, rutube.ru, список настраивается), а не запросом к Cloudflare. В таблице видны отклик по каждому сайту и отметка «RU ✘» для адресов, через которые российские сайты не открылись.
- Сканирование идёт пачками: один тестовый Xray на 40 адресов вместо отдельного процесса на каждый.


## [3.4.0] — 2026-10-16

### Added
- `autoxray warp scan [--apply] [--full] [--colo ..] [--exclude-colo ..]`: параллельная проверка адресов WARP из всех диапазонов Cloudflare, замер задержки внутри туннеля, узел и страна выхода, выбор самого быстрого. Пункт в меню WARP. Идея и диапазоны из warpscout (MIT).
- Очистка и ограничение логов Xray: без лимитов IP журналы очищаются, иначе обнуляются при размере больше 20 МБ. Проверка в `autoxray doctor`.
- В README раздел о том, какие данные хранятся на сервере.

### Changed
- `autoxray warp on` выбирает самый быстрый рабочий endpoint, а не первый рабочий.
- В `autoxray warp status` показываются узел и задержка выбранного endpoint.


## [3.3.0] — 2026-10-16

### Added
- Режим российских сайтов у каждого пользователя: `autoxray user set имя --ru direct|server` (и `--ru` при `user add`). Один клиент может открывать их напрямую с устройства, другой отправлять через сервер и WARP.
- Лимит устройств: `autoxray user set имя --ips N`, команды `autoxray ips` и `autoxray unban`. Лишние IP блокируются правилом Xray на 30 минут, лог доступа включается только при заданных лимитах и очищается раз в минуту.
- В списке версий ядра показываются пререлизы с пометкой и отдельным предупреждением.
- В `autoxray user list` колонки RU и IP, в `autoxray warp status` подробное объяснение маршрутизации и режимы пользователей.
- Расписание обновляется командой `autoxray setup-cron` (вызывается установщиком и `self-update`).

### Changed
- `autoxray warp ru on` больше не меняет подписки: он только отправляет через WARP российские сайты, дошедшие до сервера. Режим клиента задаётся для каждого пользователя отдельно. Существующим пользователям при обновлении сохраняется их прежнее поведение.
- Установщик подробнее объясняет, как работает WARP.
- В названии XHTTP-ссылки убрана приписка «для моста».


## [3.2.0] — 2026-10-16

### Added
- Строка о новой версии autoxray в шапке меню и в `autoxray status` (кэш обновляется раз в 12 часов из cron, меню не ждёт сеть).
- `autoxray core list` и `autoxray core update`: текущая версия Xray, версии новее неё, предупреждение «не обновлять без необходимости», подтверждение и автоматический откат, если конфиг не проходит проверку на новой версии.

### Changed

- Endpoint WARP по умолчанию задан IP-адресом, а не именем.
- README переписан.

## [3.0.0] — 2026-10-16

Полная переработка. Один установщик, один CLI, одно состояние.

### Added
- `autoxray` — CLI и текстовое меню: пользователи, лимиты трафика и сроки, ежемесячный сброс, статистика, бэкап и восстановление, обновление (`self-update`), удаление.
- Несколько пользователей: у каждого свои UUID, пароль Hysteria2 и личная страница подписки; отзыв доступа не затрагивает остальных.
- Учёт трафика по пользователям (статистика Xray) и заголовок `subscription-userinfo` в подписках.
- Cloudflare WARP как встроенный `wireguard`-outbound Xray: свой список доменов и режим «российские сайты через WARP».
- Режим моста RU → EU в том же установщике (`install.sh домен vless://...`), узлы управляются через `autoxray node`.
- Новая адаптивная страница подписки (светлая/тёмная тема, QR, кнопки Happ и v2rayTun, остаток трафика).
- Перенос установки autoXRAY 2 (`autoxray migrate`, запускается установщиком автоматически): UUID, ключи и ссылка подписки сохраняются.
- Docker-тесты (`tests/run.sh`): настоящие Xray и nginx, трафик через все протоколы, мост из двух контейнеров, установщик и миграция.
- Система релизов: `VERSION`, CHANGELOG, CI, автоматическая публикация релиза по тегу.

### Changed
- Конфиги Xray, nginx и подписок собираются из `/etc/autoxray/state.json` (`autoxray render`); правка `config.json` вручную больше не сохраняется.
- Закрытый ключ TLS доступен только root и группе, под которой работает xray (раньше `644` для всех).
- Новый конфиг Xray проверяется `xray run -test` перед применением, при ошибке остаётся прежний.
- Установщик останавливается на ошибках (apt, Xray, сертификат, `nginx -t`), проверка DNS учитывает несколько A-записей и внешний адрес.
- Путь формы входа на сайте-маскировке выбирается случайно.

### Removed
- Устаревшие скрипты (`old/`), тестовые копии (`test/`), отдельный `bridgeTLSxhttp.sh`, `warp-cli`-схема.
